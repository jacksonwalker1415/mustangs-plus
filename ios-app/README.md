# SMU+ iOS app (Capacitor)

A native iPhone shell for the SMU+ website. **Concept built for an SMU Cox MBA class project.** Not affiliated with or endorsed by SMU Athletics or Learfield. It is not in the App Store.

Nothing in `ios-app/` is used by the website. GitHub Pages publishes the repo root and the site never links to anything here.

## What's here

| Path | What it is |
| --- | --- |
| `capacitor.config.json` | App id `io.github.jacksonwalker1415.smuplus`, name `SMU+`, web folder `www`, SMU blue `#354CA1` background, splash and status bar settings |
| `package.json` | Capacitor 8: core, cli, ios, app, haptics, share, splash-screen, status-bar |
| `scripts/copy-web.mjs` | Copies the site from the repo root into `www/` and adds the native shim. It leaves the website untouched. |
| `native/native.js`, `native/native.css` | Native-only features: bottom tab bar, Sports sheet, share sheet, haptics, status bar, splash hide, deep links. They run only when `window.Capacitor` reports a native platform. |
| `ios/` | Xcode project generated by `npx cap add ios` (Swift Package Manager, no CocoaPods) |
| `ios/App/App/SceneDelegate.swift` | Adds `MultiPageRouter`, explained below |
| `ios/App/App/Assets.xcassets` | App icon (one 1024×1024 image) and launch image (2732×2732) |
| `resources/` | Source images for the icon and launch screen |

`www/`, `node_modules/` and `ios/App/App/public/` are generated and are not in git.

### Bundled site vs. loading the live URL

The app **bundles a copy of the site** (`webDir: www`, refreshed by `npm run sync`). The alternative would be setting `server.url` to the live GitHub Pages URL.

| | Bundled (chosen) | `server.url` to the live site |
| --- | --- | --- |
| Opens offline / on bad signal | Pages, styles, photos and scripts are on the phone | Blank page without a connection |
| Startup speed | Instant (files are local) | Network every launch |
| Content updates | Rebuild the app (`npm run sync`, then Run in Xcode) | Every push to `main` shows up right away |
| App Store review (later) | Counts as app content | Apple often rejects apps that are only a remote website (guideline 4.2) |
| Live data (Supabase, videos, X posts) | Still loaded live over the network | Same |

To try the live-site mode for a demo, add `"server": { "url": "https://jacksonwalker1415.github.io/mustangs-plus/" }` to `capacitor.config.json` and run `npx cap sync ios`. Don't commit that change.

### Why there is a custom router

Capacitor serves the app from `capacitor://localhost/`. Its default router assumes a single-page app: every path without a file extension, such as `/library/`, gets the root `index.html`. SMU+ has a separate `index.html` in each folder. `MultiPageRouter` in `SceneDelegate.swift` serves `<folder>/index.html` when that file exists and falls back to the root page otherwise. It refuses paths that escape the bundle. `SceneDelegate` and `Main.storyboard` use `SMUBridgeViewController`, which installs this router.

## Run it on your iPhone (Mac, free Apple ID)

You need a Mac with **Xcode 26 or newer** (free from the Mac App Store), **Node 22 or newer**, a USB cable, and your normal Apple ID. You don't need the paid Developer Program for this.

1. Get the code and install the dependencies:
   ```bash
   git clone https://github.com/jacksonwalker1415/mustangs-plus.git
   cd mustangs-plus && git checkout bot/ios-capacitor
   cd ios-app
   npm install
   ```
2. Copy the site into the app and update the Xcode project:
   ```bash
   npm run sync        # = node scripts/copy-web.mjs && npx cap sync ios
   ```
3. Open Xcode with `npm run open`, or open `ios/App/App.xcodeproj`. The first open downloads the Swift packages, which takes a minute or two.
4. Sign the app with your free personal team:
   - In the left sidebar click **App** (blue icon), select the **App** target, then open **Signing & Capabilities**.
   - Keep **Automatically manage signing** checked.
   - Open **Team**, choose **Add an Account…**, sign in with your Apple ID, then pick **Your Name (Personal Team)**.
   - If Xcode says the bundle identifier isn't available, change it to something unique, such as `io.github.jacksonwalker1415.smuplus.jw`.
5. Prepare the iPhone:
   - Plug it in, unlock it, and tap **Trust** on "Trust This Computer?".
   - Turn on **Developer Mode** under Settings → Privacy & Security → Developer Mode. The phone restarts; confirm **Turn On** afterward. The switch appears only after the phone has been connected to Xcode once.
6. In Xcode's toolbar, pick your iPhone as the run destination and press **Run** (⌘R).
7. The first launch is blocked with "Untrusted Developer". On the iPhone go to Settings → General → **VPN & Device Management**, tap your Apple ID under Developer App, then tap **Trust**. Open SMU+ from the home screen.

Limits of a free personal team:

- The app stops opening **7 days** after you install it. Plug in and press Run again to renew it.
- At most 3 of your own apps can be installed on the device at once.
- There is no TestFlight and no sharing with other people.

To update the app after the website changes, pull, run `npm run sync`, and press Run again.

## Sign-in inside the app (Supabase)

- **Email + password sign-in and sign-up work in the app as-is.** Supabase's API accepts requests from the app's `capacitor://localhost` origin. supabase-js loads from the jsDelivr CDN, so sign-in needs a connection. The app keeps its own session, separate from Safari's.
- **Email links** (confirm sign-up, magic link, password reset, student sign-up) are built from `SITE_URL` in `assets/config.js`. By default they point at the live website, so tapping one opens Safari and signs you in there, not in the app. Nothing breaks.
- **Optional: have email links open the app.** Nothing below has been done; it needs Jackson's OK.
  1. In the Supabase dashboard, open Authentication → URL Configuration → Redirect URLs and add `smuplus://app/**`. Leave the Site URL and the existing website URLs as they are.
  2. Build with `SMU_NATIVE_AUTH_REDIRECT=1 npm run sync`. This changes `SITE_URL` to `smuplus://app/` in the app's bundled copy only. The website keeps its own `config.js`.
  3. The app already registers the `smuplus` URL scheme (`Info.plist`), and `native.js` turns `smuplus://app/account/#access_token=…` into the in-app Account page, where supabase-js picks up the session.

  Tradeoff: emails sent from an app built this way only open on a phone with the app installed. A link opened on a laptop fails. If `smuplus://app/**` isn't on the allow list, Supabase sends the link to the Site URL instead. Use this for a device demo and keep the default otherwise.

## Native features (app only)

- **Bottom tab bar:** Home, Watch (`library/`), Sports (a sheet with all 12 sport pages), Boards (`boards/`) and Account (`account/`). It sits above the home indicator, highlights the current section, and tapping the current tab scrolls to the top.
- **Share:** the reader's **Share** button opens the iOS share sheet with the public `https://jacksonwalker1415.github.io/mustangs-plus/...` link. If the native sheet fails it falls back to the Web Share API. On the website that button keeps its existing demo behavior.
- **Haptics:** a light tap on tab and Sports-sheet taps, red buttons, Join, form submits and the menu button.
- **Status bar and launch:** light status-bar text over the SMU blue header strip. The launch screen is flat SMU blue with the centered SMU+ logo, matching the site's loading screen, and hides as soon as the first page is ready.
- **No service worker or web manifest** inside the app. `copy-web.mjs` strips both, because the app's files are already local.

## Later: TestFlight (needs Jackson's approval, costs money)

TestFlight requires the **Apple Developer Program ($99/year)**. Nobody has signed up; Jackson decides.

If approved:

1. Enroll at developer.apple.com.
2. In App Store Connect, create an app record with the bundle id.
3. In Xcode, pick the paid team under Signing, choose **Any iOS Device**, then Product → **Archive** → **Distribute App** → **App Store Connect** → Upload.
4. Add testers in TestFlight:
   - **Internal testers:** up to 100 people on the team. No review.
   - **External testers:** up to 10,000, by email or public link. Needs a short Beta App Review.

Builds expire after 90 days.

A public App Store release would also need SMU's permission to use its marks, and probably more native features to pass guideline 4.2. That is out of scope for this concept.

## Notes for maintainers

- After `npm run sync`, this folder contains HTML copies of the site in `www/` and `ios/App/App/public/`. Run `rm -rf ios-app/www ios-app/ios/App/App/public` before running site-wide scripts that search every `*.html` in the repo, such as `build_pages.py` or the PWA head-block script, so they don't edit or count the copies.
- `npx cap sync` rewrites `ios/App/CapApp-SPM/Package.swift` and copies the config. It doesn't touch `SceneDelegate.swift`, `Info.plist` or the asset catalogs, so the customizations survive.
- **Testing without a Mac:** serve `ios-app/www/` at `/` and load it in a browser with a stub `window.Capacitor` that has `isNativePlatform: () => true`, `nativePromise` and `nativeCallback`. The tab bar and the other native features turn on.
